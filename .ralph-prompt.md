# Ralph Loop Prompt — PG Master build

You are building the PG Master app by working through `TASKS.md` one task at a time.

## Each iteration, do exactly this:

1. **Read `TASKS.md`.** Find the FIRST task marked `[ ]` (todo). That is your only task this
   iteration. Do not skip ahead. Do not batch multiple tasks.

2. **Read the relevant spec** if the task references one (`DESIGN.md`, `CURRICULUM.md`,
   `MASTERY-INSIGHTS.md`, `DATASET.md`) — the specs are the source of truth for content and
   data. Match them exactly (e.g. table types/constraints must match `DATASET.md`).

3. **Do the task** — the smallest correct implementation that satisfies it. Follow the
   project standards: TypeScript, Next.js App Router, Tailwind, PGlite client-only. Scope
   discipline: only what the task asks, nothing speculative.

4. **Verify it works** using the task's stated `_Verify:_` step. Actually run it (build,
   dev server, or a query in PGlite) — do not check the box on hope. If it fails, fix it
   before proceeding. If you cannot verify (e.g. needs the user to look at a browser),
   say so explicitly and STOP rather than falsely marking it done.

5. **Update `TASKS.md`:** change that task's `[ ]` to `[x]`. If you learned something that
   changes later tasks, update them and note it in the decisions log.

6. **Commit** with the task's stated `_Commit:_` message (Conventional Commits).
   Commit ONLY the files for this task.

7. **Report** in 2–3 lines: what you did, how you verified it, the commit hash. Then the
   loop advances to the next task.

## Stop conditions — end the loop (do not schedule another iteration) when:

- All tasks in `TASKS.md` are `[x]`, OR
- You hit a task that genuinely needs a human decision or a human to look at the browser
  (verification you cannot perform), OR
- A task fails verification and you cannot fix it after a reasonable attempt — STOP and
  report the blocker rather than committing broken work or looping on it.

## Never:

- Never commit code that doesn't build / whose verify step failed.
- Never work on a task out of order or do more than one task per iteration.
- Never fabricate a verification. If you didn't actually run it, say so.
